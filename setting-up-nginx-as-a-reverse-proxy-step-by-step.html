Setting up Nginx as a reverse proxy, step by step

If you're running a Node, Python, or Go app on a $6/month VPS, you almost certainly need a reverse proxy sitting in front of it. Nginx is the go-to choice — it's fast, stable, and handles SSL termination, static file serving, and load balancing without breaking a sweat. This guide walks you through the whole setup from a fresh Ubuntu 22.04 server to a working proxy with HTTPS. Expect to spend about 20 minutes.

Why bother with a reverse proxy?

Your app likely runs on a high port like 3000 or 8080. You can't easily expose that on port 80/443 without root privileges, and you definitely don't want your app handling raw TLS or serving static assets directly. Nginx sits between the internet and your app, forwarding real traffic while handling the boring infrastructure layer. It also means zero downtime restarts — Nginx keeps accepting connections while you bounce your app.

Step 1: Install Nginx

On Ubuntu/Debian, this is a one-liner:

sudo apt update && sudo apt install nginx -y

Once installed, check it's running:

sudo systemctl status nginx

You should see active (running). Hitting your server's IP in a browser should show the default Nginx welcome page. If your firewall is blocking it, open ports 80 and 443:

sudo ufw allow 'Nginx Full'

Step 2: Create a server block for your app

Nginx uses "server blocks" (equivalent to Apache's virtual hosts). Don't edit the default config — create a new file instead. Let's say your domain is api.yourapp.com and your app runs on port 3000:

sudo nano /etc/nginx/sites-available/api.yourapp.com

Paste in this config:

server {
    listen 80;
    server_name api.yourapp.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}

The X-Real-IP and X-Forwarded-For headers are important — without them, your app sees every request coming from 127.0.0.1 instead of the real client IP. The Upgrade and Connection headers keep WebSocket connections alive if your app uses them.

Step 3: Enable the site and test

Symlink the config into sites-enabled, then test for syntax errors before reloading:

sudo ln -s /etc/nginx/sites-available/api.yourapp.com /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

nginx -t is your safety net — always run it before reloading. A typo in your config won't take down the running server, but it will prevent the reload from applying.

Step 4: Add HTTPS with Certbot

Free TLS via Let's Encrypt takes about two minutes. Install Certbot:

sudo apt install certbot python3-certbot-nginx -y
sudo certbot --nginx -d api.yourapp.com

Certbot automatically edits your server block to redirect HTTP to HTTPS and adds the certificate paths. Your config will now have a listen 443 ssl block added automatically. Certificates auto-renew via a systemd timer — verify it with:

sudo systemctl status certbot.timer

Step 5: Tune for performance

The default config is fine for light traffic, but a few tweaks make a real difference under load.

Enable gzip compression

Open /etc/nginx/nginx.conf and make sure this block is active:

gzip on;
gzip_types text/plain application/json application/javascript text/css;
gzip_min_length 1000;

Set reasonable timeouts and buffer sizes

Add these inside your server or http block:

proxy_connect_timeout 60s;
proxy_send_timeout 60s;
proxy_read_timeout 60s;
client_max_body_size 10m;

The client_max_body_size default is 1MB — increase it if you accept file uploads.

Quick benchmark check

Once everything's running, do a sanity check with wrk or ab:

ab -n 1000 -c 50 https://api.yourapp.com/health

A basic Express or FastAPI app behind Nginx on a $6 DigitalOcean Droplet (1 vCPU, 1GB RAM) should handle 500–1500 req/s on a simple endpoint without sweating. If you're seeing much lower numbers, check whether your bottleneck is the app or the proxy by hitting 127.0.0.1:3000 directly from the server.

Common gotchas

  • 502 Bad Gateway — your app isn't running, or it's on a different port than you configured. Check with ss -tlnp | grep 3000.
  • Mixed content warnings — set X-Forwarded-Proto and make sure your app trusts proxy headers (in Express: app.set('trust proxy', 1)).
  • WebSocket timeouts — add proxy_read_timeout 3600s; for long-lived connections.
  • Forgetting to reload — editing a config file does nothing until you run sudo systemctl reload nginx.

That's the full setup. You now have Nginx proxying traffic to your app, HTTPS handled automatically, and a baseline performance-tuned config. From here you can layer on rate limiting (limit_req_zone), caching, or even basic load balancing across multiple app instances — all without touching your application code.
