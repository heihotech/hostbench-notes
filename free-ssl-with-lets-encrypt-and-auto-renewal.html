Free SSL with Let's Encrypt and auto-renewal

Paying for an SSL certificate used to be a genuine line item—anywhere from $10 to a few hundred dollars a year depending on your CA and validation level. Let's Encrypt killed that model in 2016 and the internet got measurably more secure overnight. Today you can get a fully trusted, auto-renewing certificate on a fresh VPS in about ten minutes. Here's exactly how to do it.

Why Let's Encrypt Still Wins

Let's Encrypt issues Domain Validated (DV) certificates, which is all you need for 99% of projects. The cert is trusted by every major browser, it's free forever, and the 90-day expiry is a feature not a bug—it forces automation, which means you're far less likely to wake up to a surprise expiry at 2am. The non-profit behind it (ISRG) processes over 300 million active certificates, so it's not going anywhere.

What You'll Need

  • A VPS or dedicated server (DigitalOcean, Hetzner, Vultr—anything works)
  • A domain name pointing at that server's IP via an A record
  • Ports 80 and 443 open in your firewall
  • Nginx or Apache installed (we'll use Nginx throughout)

DNS propagation needs to be complete before you run the cert tool. Check with dig yourdomain.com +short and make sure the IP matches your server.

Installing Certbot

Certbot is the official ACME client from the EFF and the easiest way to talk to Let's Encrypt. On Ubuntu 22.04:

sudo apt update
sudo apt install -y certbot python3-certbot-nginx

The python3-certbot-nginx plugin is the important part—it reads your Nginx config, obtains the cert, and rewrites your server blocks automatically. You don't have to touch a config file manually if you don't want to.

Getting Your First Certificate

Assuming you already have a basic Nginx server block for example.com, run:

sudo certbot --nginx -d example.com -d www.example.com

Certbot will ask for an email address (for expiry warnings, just in case automation breaks), agree to the TOS, and then spin up a temporary HTTP server to prove you control the domain. The whole handshake takes about 15 seconds. When it's done, it rewrites your Nginx config to add:

  • The certificate and key file paths
  • A redirect from port 80 to 443
  • Recommended SSL settings (TLS 1.2/1.3, strong ciphers)

Run nginx -t && systemctl reload nginx to apply the changes, then visit your site over HTTPS. You should see a padlock immediately.

Setting Up Auto-Renewal

This is where most guides get vague. Let's be specific. Certbot installs a systemd timer on Ubuntu automatically. Verify it's active:

systemctl status certbot.timer

You should see active (waiting). The timer runs twice a day and renews any certificate that's within 30 days of expiry. Because Let's Encrypt certs last 90 days, you get a comfortable 60-day window where nothing needs to happen, then a 30-day auto-renewal window.

If you're on an older system or prefer cron, add this instead:

0 3 * * * certbot renew --quiet --post-hook "systemctl reload nginx"

The --post-hook flag is critical—it reloads Nginx only when a renewal actually happens, so you're not bouncing your server twice a day for nothing.

Testing the Renewal Process

Don't wait 60 days to find out if it works. Do a dry run right now:

sudo certbot renew --dry-run

A successful output ends with Congratulations, all simulated renewals succeeded. If you see errors here, fix them while you still have months of runway left.

Wildcard Certificates

If you're running subdomains—api.example.com, app.example.com, staging.example.com—a wildcard cert cleans things up. Let's Encrypt issues wildcards via DNS-01 challenge instead of HTTP-01, which means you need to add a TXT record to your DNS to prove ownership.

sudo certbot certonly --manual --preferred-challenges dns \
  -d "*.example.com" -d example.com

Certbot will pause and tell you exactly what TXT record to add. Once you add it (and wait 30–60 seconds for propagation), press Enter and the cert is issued. Automating wildcard renewal requires a DNS plugin for your provider—DigitalOcean, Cloudflare, and Route53 all have official ones.

Quick Benchmark Check

After setup, run your domain through SSL Labs. A fresh Certbot-managed Nginx config typically scores an A out of the box—TLS 1.3 support, no weak ciphers, HSTS header in place. To push to A+, add a long-duration HSTS header with preload directive and submit to the browser preload lists, but that's a one-way door so only do it when you're confident in your setup.

Cost Summary

  • SSL certificate: $0/year
  • Certbot: $0, open source
  • Your time: ~10 minutes for initial setup, ~0 minutes ongoing

The only real cost is the server itself. A Hetzner CX22 runs about €4/month and handles this setup without breaking a sweat. There's genuinely no reason to pay for a standard DV cert anymore—spend that budget on something that actually moves the needle for your project.
