Deploying a static site to a $5 VPS in 10 minutes

Managed hosting platforms are convenient until you see the bill. Netlify, Vercel, and friends are great, but once you need a custom server config, private networking, or you just want to understand what's actually happening under the hood, a cheap VPS is hard to beat. A $5/month Hetzner or DigitalOcean droplet running Nginx can serve a static site to thousands of visitors without breaking a sweat — and you'll own the whole stack. Here's how to get there in about ten minutes.

What You'll Need

  • A VPS — Hetzner Cloud CX11 ($4.15/mo) or DigitalOcean Basic Droplet ($6/mo) both work fine
  • Ubuntu 22.04 LTS (the examples below assume this)
  • A domain name pointed at your server's IP
  • Your static site files (a plain HTML folder, a built Astro/Next export, whatever)
  • SSH access to the server

Step 1: Provision the Server (2 minutes)

Spin up the smallest available instance. On Hetzner, that's a CX11 with 1 vCPU and 2 GB RAM. On DigitalOcean it's their 1 GB Basic droplet — bump it to the $6 tier for 1 GB RAM if you can. Add your SSH public key during setup so you skip password auth entirely.

Once it's live, SSH in:

ssh root@YOUR_SERVER_IP

Run a quick update before touching anything else:

apt update && apt upgrade -y

Step 2: Install Nginx (1 minute)

Nginx is lightweight, battle-tested, and dead simple to configure for static files. Install it and make sure it starts on boot:

apt install nginx -y
systemctl enable nginx
systemctl start nginx

Visit your server's IP in a browser. You should see the default Nginx welcome page. That's your green light.

Step 3: Upload Your Site Files (2 minutes)

The default web root is /var/www/html. You can either drop your files there or create a dedicated directory — the latter is cleaner if you're hosting multiple sites later.

mkdir -p /var/www/mysite
chown -R www-data:www-data /var/www/mysite

From your local machine, use rsync to push your build folder up. If your static site lives in a dist/ directory (common with Astro, Vite, or Eleventy builds):

rsync -avz --delete ./dist/ root@YOUR_SERVER_IP:/var/www/mysite/

The --delete flag removes stale files on the server that no longer exist locally. Useful when you re-deploy after removing pages.

Step 4: Configure Nginx (2 minutes)

Create a new server block instead of editing the default config:

nano /etc/nginx/sites-available/mysite

Paste this in, swapping out the domain and path:

server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;

    root /var/www/mysite;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    # Cache static assets aggressively
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}

Enable the config and reload Nginx:

ln -s /etc/nginx/sites-available/mysite /etc/nginx/sites-enabled/
nginx -t
systemctl reload nginx

nginx -t is your best friend — always test the config before reloading to avoid downtime from a typo.

Step 5: Add HTTPS with Certbot (2 minutes)

No excuses for shipping without TLS in 2024. Certbot makes it free and nearly automatic:

apt install certbot python3-certbot-nginx -y
certbot --nginx -d yourdomain.com -d www.yourdomain.com

Follow the prompts, choose option 2 to redirect HTTP to HTTPS, and Certbot will rewrite your Nginx config automatically. Certificates auto-renew via a systemd timer — you never have to think about it again.

What Kind of Traffic Can This Handle?

More than you'd expect. Nginx serving pre-built HTML and cached assets is extraordinarily efficient. A $5-6 VPS can comfortably handle several hundred concurrent connections and well over 1,000 requests per second for typical static content. Run a quick benchmark from your local machine with wrk to see for yourself:

wrk -t4 -c100 -d30s https://yourdomain.com

On a Hetzner CX11 with a simple HTML page, you'll typically see 8,000–15,000 requests/second. That's enough headroom for a product launch spike or a sudden burst of traffic from a newsletter.

Automating Future Deploys

Once this is working, the natural next step is wiring it into your CI pipeline. A GitHub Actions workflow that runs rsync after a successful build takes about 15 minutes to set up and means every push to main automatically updates the live site. Store your SSH private key as a GitHub secret, point it at your server, and you've got a lightweight CD pipeline for under $6 a month total.

A Few Extras Worth Adding

  • UFW firewall: ufw allow 'Nginx Full' && ufw enable — do this early
  • Fail2ban: blocks brute-force SSH attempts automatically
  • Gzip compression: add gzip on; to your Nginx config for smaller payloads
  • Monitoring: even a free UptimeRobot check gives you uptime alerts

The whole setup costs less than a coffee per month and gives you complete control. Once you've done it once, the muscle memory sticks — next time you'll have a site live in five minutes, not ten.
