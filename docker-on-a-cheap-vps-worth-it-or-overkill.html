Docker on a cheap VPS: worth it or overkill

You've got a $6/month VPS from Hetzner or a $4 droplet from DigitalOcean, and you're wondering whether slapping Docker on it makes any sense. It's a fair question. Docker carries a reputation for being a "serious infrastructure" tool, but the reality is that it runs just fine on a single cheap server — and in many cases, it genuinely makes your life easier. Let's break down when it's worth it, when it's overkill, and how to actually set it up without wasting half a Saturday.

What You're Actually Paying in Resources

Docker itself has a modest footprint. The daemon idles at around 30–80MB of RAM depending on how many containers are running. On a 1GB VPS, that's noticeable but workable. On 2GB, you won't think about it twice. The real cost isn't Docker — it's the containers you run inside it.

Here's a rough baseline for common indie dev workloads:

  • Nginx (Alpine-based): ~5–10MB RAM
  • Node.js app: 80–200MB depending on your app
  • PostgreSQL container: 50–150MB at idle
  • Redis: ~10–30MB

A typical three-container setup (web app + database + cache) can sit comfortably under 512MB of actual usage. On a $6 Hetzner CAX11 (2 vCPU, 4GB RAM, ARM64), you'll have plenty of headroom. Even the $4 DigitalOcean droplet at 512MB RAM can handle a single small container if you're careful — though I wouldn't recommend it for anything with a database.

The Real Argument For Docker on a Small VPS

The case for Docker isn't performance — it's reproducibility and sanity. Here's what changes when you containerize even a simple app:

  • Your local environment matches production exactly. No more "works on my machine" when you're the only developer.
  • Deployments become a docker compose pull && docker compose up -d instead of a ritual of SSH commands and crossed fingers.
  • Rolling back means running the previous image tag, not manually reverting files.
  • Adding a second service (say, a background worker) is a few lines in your compose file, not a new setup adventure.

For a side project or a small SaaS app with paying users, these aren't luxury features. They're the difference between a confident deployment and a 2am rollback panic.

A Minimal Setup That Actually Works

Here's a realistic starting point for a Node.js app with Postgres on a cheap VPS. After installing Docker (the official convenience script works fine for Ubuntu 22.04), create a docker-compose.yml:

services:
  app:
    image: ghcr.io/yourname/yourapp:latest
    restart: unless-stopped
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://app:secret@db:5432/appdb
    depends_on:
      - db

  db:
    image: postgres:16-alpine
    restart: unless-stopped
    volumes:
      - pgdata:/var/lib/postgresql/data
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: appdb

volumes:
  pgdata:

Put Nginx or Caddy in front of this (either containerized or installed directly on the host — both work), point your domain at the server, and you have a production-ready setup that deploys in under a minute and survives reboots automatically.

One Gotcha: Swapfile

On servers with 1GB RAM or less, add a 1GB swapfile before you do anything else. Docker image pulls and container builds can spike memory hard, and without swap you'll hit the OOM killer mid-deploy.

fallocate -l 1G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

When It Actually Is Overkill

Let's be honest about the cases where Docker adds friction without payoff:

  • A static site: Just use Nginx directly, or better yet, Cloudflare Pages. Docker is unnecessary indirection here.
  • A single PHP app with shared hosting needs: If you're running one WordPress site and never deploying code, Docker solves problems you don't have.
  • Extremely RAM-constrained servers: The free tier Oracle ARM instance has 1GB RAM and it works, but you're playing Tetris with memory. Evaluate carefully.
  • Teams with no Docker experience: If your co-founder has never touched Docker and will be doing deployments solo, the learning curve becomes an ops liability. Start simpler.

The Benchmark Angle

In practical terms, containerized apps run within a few percent of bare-metal performance for typical web workloads. The overhead is real but negligible for anything that isn't CPU-bound. If you're running a video transcoding job or a machine learning inference server on a $6 VPS, you've got bigger problems than Docker overhead.

Where you do notice cost is cold starts — pulling a 200MB image on a fresh deploy takes 10–20 seconds on a slow VPS network connection. Keep your images lean (multi-stage builds, Alpine base images) and this stops being an issue.

The Verdict

For most indie developers shipping real software, Docker on a cheap VPS hits a genuinely sweet spot. You get professional deployment hygiene, easy local-to-production parity, and a clear upgrade path (adding more containers, eventually moving to a managed cluster) without paying cloud-native prices. The overhead is real but small. The developer experience improvement is substantial. On anything with 2GB of RAM and a real app to run, it's worth it.
